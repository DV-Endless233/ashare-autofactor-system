# Grillme 审查模式 → 反直觉质疑的适应原因

## 背景

Grillme 是一种攻防对话式审查模式——审查者不直接给 verdict，而是连环追问、逐层质疑，逼被审查者辩护自己的设计，直到再无疑问才放行。

## 为何不能直接采用

| 维度 | 当前结构化审查 | Grillme |
|------|-------------|--------|
| **交互方式** | 异步（kanban handoff → 审查 → verdict） | 同步对话 |
| **轮次** | 单轮出 verdict | 多轮攻防（3~5+ 轮） |
| **Kanban 兼容性** | ✅ 天然适配 | ❌ 严重不兼容 |

当前 kanban 架构中，dvcoder 和 evaluator **从不同时在线**：
- dvcoder 完成任务 → `kanban_block(review-required)` → 结束 session
- evaluator 被调度 → 读 handoff → 审查 → `kanban_block` → 结束 session

要实现 Grillme 的同步对话，需要：
- dvcoder 和 evaluator 在同一 task 内交替执行 → 打破角色分离原则
- 或在 kanban 评论区做 N 轮 handoff → 每轮一个 dispatch cycle，一个审查消耗 6~10 个调度

## 适应方案

Grillme 最大的价值是**反直觉质疑**——强行跳出被审查者的叙事框架，从相反角度提问。这比 checklist 的「是否满足条件 X」更能发现隐藏问题。

因此，不在架构层面引入同步对话，而是在现有结构化模板内嵌入 3 个固定反直觉质疑：

1. 如果这个因子的经济学含义是反的，什么证据会支持？
2. 变量映射中最脆弱的假设是哪一个？如果它不成立，因子还剩多少信号？
3. 这个因子在哪个市场环境下必然失效？

**效果对比：**
- 不增加 dispatch 轮次 → 零架构变动
- 多花 ~200 tokens 写 3 个质疑
- 保留了 Grillme 的**压力测试效果**，但没有它的**轮次膨胀成本**
- dvcoder 在下轮迭代中必须逐一回应 → 效果等价于异步版 Grillme

## 约束

- 这 3 个问题是必写项，不是可选项
- dvcoder 在下一轮迭代中必须逐一回应，否则不得进入算子空间
- 如果 evaluator 发现某个质疑的答案涉及方向性颠覆（如经济学含义被证伪），应该通过标准打回流程退回语义空间，而不是在 3 个问题中继续纠缠
