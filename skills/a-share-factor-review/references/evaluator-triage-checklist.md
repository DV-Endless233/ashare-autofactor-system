# Evaluator 三问审查细则

## 第一问：因子是否有明确的经济学含义？

**不要做**：
- "代码跑通了，指标达标了，所以没问题"
- "因子值和回测看起来合理"

**要做**：
- 要求 dvcoder 用一句话说清楚因子的经济学逻辑
- 检查这句话是否自洽：变量A和变量B的关系是否在经济学上有先例？
- 检查因子是否只是数学上的巧合（如两个负数的除法为正——这就是需要门控的情况）

**判断标准**：
- 有：能清楚解释"为什么A的变动会导致B的变动，从而产生选股效果"
- 无：只能解释"这个因子在历史上选股效果好"——这是回溯，不是经济学含义

## 第二问：因子是单因子还是多因子组合？

**判断规则**：
- ✅ 单因子：FCF = OCF - CapEx → 能用一个经济学名称概括
- ❌ 组合：zscore(OCF) + zscore(CapEx) - penalty(Debt) → 需要这句话才能描述

**审查步骤**：
1. 读 `formula.md` 或代码中的公式部分
2. 看表达式是否包含多个 zscore() / rank() / 标准化后的信号做加减
3. 如果包含，问：为什么系数是1而不是0.5？为什么是加法不是乘法？
4. 如果无法从经济学上回答系数问题，退回

**边界情况**：
- `A - B` 是一级运算，如果结果有单一名称（如"自由现金流"），可以
- `A / B` 是一级运算，如果结果有单一名称（如"现金利润率"），可以
- `zscore(A) + zscore(B)` 是二级运算（标准化后再组合），不可以

## 第三问：因子是否基于历史数据调整的比率/门控/奖励？

**审查步骤**：
1. 检查是否使用了条件结构（if/else、三目运算、mask、np.where、where/assign with condition）
2. 如果有，问：这个条件的经济学理由是什么？
3. 如果理由是"历史上这样表现更好"、"参数搜索发现最优"、"IC在这段区间更高" → 退回
4. 如果理由是该条件本身是经济学含义的一部分（如分子分母同时为负时比值无意义）→ 可以保留

**门控允许的唯一场景**：
- 公式本身在特定数值区间会产生经济学含义矛盾
- 例：OCF/NetProfit，当OCF<0且NetProfit<0时，比值反而为正，这与"现金利润率"的含义完全矛盾

**门控禁止的场景**：
- 基于历史最优切割点的阈值门控（如"当X>0.5时取A，否则取B"）
- 基于IC方向切换的条件门控（如"当IC为正时取A，IC为负时取B"）
- 基于分位数或排序的门控（如"只取前20%的股票"）
- 任何需要参数搜索或历史统计确定边界的门控

## 完整审查输出格式

```
## 审查结论：[通过 / 不通过 / 有条件通过]
## 第三问结果：
- 经济学含义：[清晰 / 模糊 / 无]
- 单因子判定：[是 / 否 / 边界情况需澄清]
- 历史数据依赖：[无 / 有门控需说明 / 有奖励需说明]
## 如果"不通过"：
- 回流点：[退回第几步]
- 回流理由：
  - 缺经济学解释
  - 属于多因子组合
  - 使用了无经济学依据的门控/奖励
```
