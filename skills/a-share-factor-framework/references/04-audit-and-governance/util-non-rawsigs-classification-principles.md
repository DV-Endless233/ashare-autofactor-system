# util 非 rawsigs 分类与审计原则

## 适用场景

当任务是在 `${PROJECT_ROOT}/util` 中：

- 解释某个模块的职责
- 审计非 `rawsigs` 工具层
- 输出 util 目录的分类表 / xlsx / line-check
- 判断某段逻辑该放原子层、共享层还是叶子层

先参考本 note。

## 扫描范围

- 必扫：`${PROJECT_ROOT}/util`
- 排除：`${PROJECT_ROOT}/util/rawsigs`
- 不要只看用户点名文件；需要补全 util root 下其他 `.py`

## 分类原则

### 1. 先按三层边界判断

- 原子层：`util/rawsigs/` 内的底层输入与原子信号
- 共享层：`func.py` + `util/` 非 rawsig 公共模块
- 叶子层：`*_codex.py`

### 2. 再按职责空间解释

可用的辅助标签包括：

- 数据空间
- 语义空间
- 变量映射空间
- 算子空间
- 参数空间
- 验证空间

这些标签用于解释职责，不替代三层架构本身。

## 推荐输出字段

当用户要你做 util 分类表时，优先保留下面这些列：

- `代码名`
- `类名`
- `函数名`
- `用途`
- `前置调用函数名`
- `怎么调用该函数/类`
- `参数有哪些可调`
- `用于哪个空间`

## 描述写法

- 写**独特职责**，不要只写“用于处理数据”。
- 优先交代输入对象、输出对象、在主链条中的位置。
- 若模块主要职责是缓存、股票池、中性化、回测、补算、路径管理，要直接点明。

## 典型示例

- `factorclass.py`：缓存路径与读删缓存规则。
- `stkfactorclass.py`：股票因子补算与最终写缓存主流程。
- `fiscalsigclass.py`：原子财务信号父类。
- `getStkPool.py`：股票池过滤。
- `neutfactorclass.py`：中性化。
- `stkfactorbacktest.py`：回测统计。

## xlsx / line-check 审计规则

- 行顺序优先按“因子生成 → 因子构建 → 因子回测”。
- 若同一模块兼有多职责，先写主职责，再写关键调用关系。
- 不要把旧第四层 `_codex_utils` 当作应保留的正式层级。
- 如果 line-check 发现叶子里堆了共享逻辑，应回指共享层，而不是把异常当成常态记录。

## 常见误判

- 把 `util/` 下公共模块误判成叶子层。
- 把职责标签当成目录层级。
- 因为某模块被多个因子调用，就把它写成“万能模块”而不描述具体边界。
- 审计时只看文件名，不看真正的主流程入口与被调关系。
